### Root Cause Confirmation (Bucket B: Recipe Output Contract Drift)
- Analyzed three Azure recipes: `state-store.bicep`, `pubsub.bicep`, `secrets.bicep`
- **Finding:** All three manually emit Azure resource IDs in `output result.resources`
- Consulted Radius documentation: Bicep recipes auto-populate backing resources; manual `resources` entries are for Kubernetes/UCP only
- Failing resource IDs (`storageAccounts/...`, `namespaces/...`) match manual entries
- This explains statestore and pubsub failures: ARM template cannot locate manually-emitted Azure resources

### Recommended Fix Sequence
1. **Immediate:** Register Azure credentials via `rad credential register azure` before redeployment
2. **Phase 2:** Remove manual Azure resource IDs from recipe `result.resources` blocks
3. **Phase 3:** Regenerate checked-in `.json` files from updated Bicep
4. **Phase 4:** Republish OCI recipes to registry
5. **Phase 5:** Redeploy environment and app
