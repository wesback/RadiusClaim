# Eddie: GHCR Private-by-Default Documentation Audit

## Audit Outcome

**Scope:** Reviewed documentation artifacts for explicit statements about GHCR package visibility defaults.

**Finding:** Documentation is insufficient. Current docs mention GHCR tokens and pull secrets in troubleshooting but do **not explicitly state** that GHCR packages are private by default. Operators discover this constraint only after hitting 403/401 failures at pod-start time.

## Gap Analysis

### Current State
- **Troubleshooting section** (approx line 700): Addresses "If you see 403" as an error response
- **Token creation section** (approx line 248): Describes token creation but not visibility implications
- **Build/push guidance** (approx line 367): Omits visibility decision checkpoint

### Impact
First-time operators follow happy-path: build → push → deploy. Pushing private packages unknowingly, they hit `403 Forbidden` during pod startup and must jump to troubleshooting to understand the fix. This turns a predictable operational decision into a **gotcha** rather than **expected workflow**.

## Recommendation

**Inject 3 clarity touchpoints** (non-invasive, minimal additions):

1. **Token Creation Section (after line 248)**
   - Add 3-line note: Explicitly state "GHCR packages are private by default"
   - Outline two deployment options: make images public OR configure AKS imagePullSecret auth

2. **Before Build/Push (around line 367)**
   - Add 2-sentence callout: "Visibility Decision Checkpoint"
   - Prompt operator to decide: public images or private with pull secrets?

3. **Troubleshooting Section (line 700)**
   - Reframe title from "If you see 403" to "When Images are Private: Create a Pull Secret"
   - Shift mindset from error-state to expected workflow

## Trade-offs

**Pros:**
- Eliminates the most common 403 Forbidden blocker for first-time operators
- Keeps happy-path compact (3 lines + 2 lines of additions)

**Cons:**
- Adds ~5 lines of inline text (negligible impact)
- Troubleshooting section loses "only needed if error" framing (acceptable; clarity wins)
