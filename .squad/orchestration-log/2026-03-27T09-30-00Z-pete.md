## Context

Wesley's bootstrap flow encountered an authorization failure when reusing an existing Service Principal:

```
ERROR: (AuthorizationFailed) The client '890caf69-5a38-4bf9-950d-0430352e7396' 
[...] does not have authorization to perform action 'Microsoft.Resources/subscriptions/resourcegroups/write'
```

The SPN existed but had no Contributor role assignment. Root cause: `prepare-cluster.sh --create-spn` reuse path exited after credential verification without verifying or assigning the required role.

---

## Implementation

**File:** `scripts/prepare-cluster.sh`  
**Lines Changed:** 367-408 (reuse SPN branch)  
**Lines Enhanced:** 408 (new SPN branch logging)

### Fix Details

1. **Reuse SPN path (lines 367-408):**
   - After finding existing SPN, added idempotent role assignment
   - `az role assignment create --assignee <appId> --role Contributor --scope /subscriptions/<id>` with `2>/dev/null` to suppress duplicate errors
   - If creation fails, verify with `az role assignment list` to confirm role exists
   - Only fail if both operations fail (truly missing role)
   - Added clear confirmation: `✓ Role assignment: Contributor on subscription <id>` or `already exists`

2. **New SPN path (line 408):**
   - Added explicit confirmation logging (already working, improved clarity)

3. **Idempotency Guarantee:**
   - First run: creates role, prints confirmation
   - Subsequent runs: creation fails silently, verification succeeds, prints "already exists"
   - Both paths guarantee SPN has Contributor before script completes
