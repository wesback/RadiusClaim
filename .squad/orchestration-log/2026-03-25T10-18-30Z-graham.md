## Recovery Command Path

Three sequential steps (execute in order):

### Step 1: Add GHCR Pull Auth in Namespace
**Recommended approach:** Add `imagePullSecret` for `ghcr.io/wesback/radiusclaim` namespace auth.

**Commands:**
```bash
NAMESPACE="radiusclaim-azure-radiusclaim"
GITHUB_USERNAME="wesback"
GITHUB_TOKEN="ghp_..."  # Replace with token having read:packages scope

kubectl create secret docker-registry ghcr-credentials \
  --docker-server=ghcr.io \
  --docker-username="$GITHUB_USERNAME" \
  --docker-password="$GITHUB_TOKEN" \
  -n "$NAMESPACE"

kubectl patch serviceaccount default -n "$NAMESPACE" \
  -p '{"imagePullSecrets": [{"name": "ghcr-credentials"}]}'
```

**Notes:**
- Replaces broken `sovereignapp/*` auth chain
- Enables pull from `ghcr.io/wesback/radiusclaim` registry
- If packages should be public instead, use Option A from recovery doc

---

### Step 2: Redeploy Expense-API, Workflow-Engine, Notification-SVC

**Key decision:** Use explicit tags (not `latest`). Preferred: git SHA or semver (e.g., `v1.0.0`).

**Commands:**
```bash
NAMESPACE="radiusclaim-azure-radiusclaim"
REGISTRY="ghcr.io/wesback/radiusclaim"
IMAGE_TAG="v1.0.0"  # Replace with desired tag (git SHA, semver)

# Scale down old pods
kubectl scale deployment expense-api -n "$NAMESPACE" --replicas=0
kubectl scale deployment workflow-engine -n "$NAMESPACE" --replicas=0
kubectl scale deployment notification-svc -n "$NAMESPACE" --replicas=0
sleep 10

# Update images with explicit tag
kubectl set image deployment/expense-api \
  expense-api="$REGISTRY/expense-api:$IMAGE_TAG" \
  -n "$NAMESPACE" --record

kubectl set image deployment/workflow-engine \
  workflow-engine="$REGISTRY/workflow-engine:$IMAGE_TAG" \
  -n "$NAMESPACE" --record

kubectl set image deployment/notification-svc \
  notification-svc="$REGISTRY/notification-svc:$IMAGE_TAG" \
  -n "$NAMESPACE" --record

# Scale back up
kubectl scale deployment expense-api -n "$NAMESPACE" --replicas=1
kubectl scale deployment workflow-engine -n "$NAMESPACE" --replicas=1
kubectl scale deployment notification-svc -n "$NAMESPACE" --replicas=1

# Monitor rollout
kubectl rollout status deployment/expense-api -n "$NAMESPACE" --timeout=5m
kubectl rollout status deployment/workflow-engine -n "$NAMESPACE" --timeout=5m
kubectl rollout status deployment/notification-svc -n "$NAMESPACE" --timeout=5m
```

**Notes:**
- Explicit tags prevent ambiguity (`:latest` can silently pull stale image)
- Scale-down ensures no stale pods linger
- `--record` adds annotation to rollout history

### Step 3: Verify Dapr Components; Redeploy Radius If Missing

**Check:**
```bash
NAMESPACE="radiusclaim-azure-radiusclaim"
kubectl get components -n "$NAMESPACE"
```

**Expected output:**
```
NAME               TYPE                              VERSION   AGE
statestore         state.azure.blobstorage           v1        ...
pubsub             pubsub.azure.servicebus           v1        ...
platform-secrets   secretstores.azure.keyvault       v1        ...
```

**If missing, redeploy Radius (Dapr components are Radius-owned):**
```bash
export KUBECONFIG="/path/to/kubeconfig"
WORKSPACE="radiusclaim-main"
ENVIRONMENT="azure"
RESOURCE_GROUP="radiusclaim-rg"
LOCATION="eastus"
NAMESPACE="radiusclaim-azure-radiusclaim"

./rad workspace switch "$WORKSPACE"
./rad group switch radiusclaim -w "$WORKSPACE"
./rad env switch "$ENVIRONMENT"

./rad deploy infra/radius/environments/azure-radius.bicep \
  --parameters environmentName="$ENVIRONMENT" \
  --parameters kubernetesNamespace="$NAMESPACE" \
  --parameters location="$LOCATION" \
  --parameters azureProviderScope="/subscriptions/<SUB_ID>/resourceGroups/$RESOURCE_GROUP"

# Verify
kubectl get components -n "$NAMESPACE"
```

**Notes:**
- Dapr components are created and managed by Radius, not by manual K8s manifests
- `rad deploy` is idempotent; safe to re-run
- If daprd sidecars still fail after components exist, check app container logs and verify port configuration

## Key Design Decisions

1. **GHCR Auth over public packages:** Keeps control over image distribution; production-ready pattern
2. **Explicit tags over :latest:** Prevents silent stale-image pulls; enables rollback traceability
3. **Radius ownership of Dapr components:** Components created by `rad deploy`, not manual K8s YAML
4. **Scale-down before redeploy:** Ensures old pods don't linger; forces fresh image pull
