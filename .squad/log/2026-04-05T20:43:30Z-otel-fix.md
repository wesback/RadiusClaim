# Session Log: OpenTelemetry Jaeger Fix

**Timestamp:** 2026-04-05T20:43:30Z  
**Summary:** Resolved Docker build blocking issue caused by unavailable OpenTelemetry.Exporter.Jaeger 1.11.0 on NuGet. Root cause: ecosystem fragmentation (Jaeger exporter lagging at 1.5.1 stable). Implemented downgrade to 1.5.1 stable across all three services (expense-api, workflow-engine, notification-svc) with zero code impact. Docker builds and service startup verified.

## What Happened

1. **Discovery** (Daisy): Identified Docker build failure during `dotnet restore`. All three core services specify `OpenTelemetry.Exporter.Jaeger >= 1.11.0`, but NuGet shows latest stable is 1.5.1; no 1.11.0 exists.

2. **Analysis** (Daisy): Root cause is OpenTelemetry ecosystem lag — while core packages reached 1.11.0 stable, Jaeger exporter is stuck at 1.6.0-rc.1 (pre-release) and 1.5.1 (stable). Evaluated four options:
   - Option A: Downgrade to 1.5.1 (recommended)
   - Option B: Use pre-release 1.6.0-rc.1
   - Option C: Wait for 1.11.0-rc.x (blocks Phase 7)
   - Option D: Switch to Application Insights (requires refactor)

3. **Implementation** (Billy): Applied Option A — downgraded to 1.5.1 across all three `.csproj` files. Verified:
   - ✅ Docker restore succeeds
   - ✅ Services compile
   - ✅ Zero code changes required (API compatible)
   - ✅ Jaeger exporter initializes cleanly

4. **Decision merged:** Documented in decisions.md for team visibility.
