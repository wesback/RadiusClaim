# Session: SPN Contributor Role Assignment Fix

**Agent:** Pete (Infrastructure Automation Specialist)  
**Work:** Idempotent Contributor role assignment for service principals  
**Outcome:** Fix implemented; bootstrap reuse path now guarantees permissions

## Summary

Fixed critical SPN reuse path in `prepare-cluster.sh`. When an existing SPN was selected for reuse, the script exited after credential verification without verifying or assigning the Contributor role. This caused Wesley's bootstrap to fail with authorization errors.

## Implementation

**Changes to `scripts/prepare-cluster.sh` (lines 367-408):**

1. After SPN credentials are verified, attempt to create the Contributor role assignment
2. If creation fails (likely "already exists"), verify the role is present using `az role assignment list`
3. Only fail if both operations fail
4. Print clear confirmation message: `✓ Role assignment: Contributor on subscription <id>`

**Result:**
- First run: role gets created
- Subsequent runs: role creation fails silently, verification succeeds
- Both paths (new and reuse) guarantee Contributor role before script completes

## Technical Details

- Subscription-level scope: `/subscriptions/{id}` (not resource group, which might not exist yet)
- Idempotent design: `2>/dev/null` suppresses "already exists" errors on creation attempt
- Verification fallback: ensures operator visibility if role truly missing
